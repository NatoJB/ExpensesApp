**Root cause.** This is not an Air authentication bug — it is Google retiring the client Air
depends on. Google announced the Gemini CLI → Antigravity CLI transition on **2026-05-19**, and on
**2026-06-18** Gemini Code Assist stopped serving the *individuals*, Google AI Pro and Google AI
Ultra tiers; "Login with Google" no longer grants access to Gemini CLI at all. Air bundles a
JetBrains fork of `gemini-cli` that still uses the retired OAuth client, so the token exchange
fails server-side. Kacper Pieszyk captured the exact failure on AIR-5394:

```
💥ERROR💥 26040:WS:SUPERVISOR  google.oauth] Failed to fetch Code Assist info for Google OAuth
token: Gemini Code Assist for individuals: This client is no longer supported for Gemini Code
Assist for individuals. To continue using Gemini, please migrate to the Antigravity suite of
products: https://antigravity.google
```

That log line is the best starting point for whoever picks this up — the `google.oauth` path in
the supervisor is where the failure surfaces.

**On the "hangs" part — this is a second, separable defect.** The reporter's primary complaint is
that the flow *hangs waiting for login in the browser* before eventually erroring. Google returns
a clear, actionable message; Air swallows it and stalls. That UX bug will still be worth fixing
after the `agy` migration, because Standard/Enterprise-ineligible accounts will keep hitting
rejections. It is already tracked as
[AIR-6262 — Endless Google auth if account is not eligible for Gemini Code Assist for individuals](https://youtrack.jetbrains.com/issue/AIR-6262)
(Open, Subsystem `Licensing`, Valerii Tepliakov). Recommend linking AIR-6823 to AIR-6262 as

**Notes for whoever implements the migration:**

- The new binary is `agy` (Antigravity CLI) — a **closed-source Go binary**, installed via
  `curl`/PowerShell rather than npm. Any Air code that installs or invokes `gemini` via npm needs
  reworking, not just renaming.
- `agy` reuses the same `~/.gemini` home directory and can import MCP servers, allowed commands,
  keybindings and theme via `agy plugin import gemini` (non-destructive). Air's existing Gemini
  config handling may be largely reusable.
- `agy` and `gemini` can coexist on one machine, which allows a staged cutover for users still on
  a paid API key.
- Known gaps at launch that may affect Air's integration: no `--yolo` flag (replaced by
  `/permissions` + Shift-Tab modes), `/extensions` replaced by `/skills`, and no AI Studio API-key
  login path.
- Official migration docs: <https://antigravity.google/docs/gcli-migration>
