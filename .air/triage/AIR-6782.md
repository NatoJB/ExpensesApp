### Root cause hypothesis (high confidence): the path is never percent-decoded

In the failing log line the path is:


Note `Application%20Support` — a literal `%20` where a space belongs, in **both** `path=` and `originalArgument=`. So `OpenFilesInLocalWorkspace` is resolving a percent-encoded *URL* string as a *filesystem* path. That directory does not exist under that literal name, which explains both halves of the message: the lookup fails (`file does not exist`) and the fallback create fails too (`failed to be created`), because the parent `Application%20Support` doesn't exist either.
