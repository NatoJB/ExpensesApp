## Wider theme: Air does not honor agents' native on-disk config

The same shape recurs once per agent, which suggests **one architectural cause rather than five
separate bugs**:

- **AIR-6772** — Junie: `.junie/guidelines.md` ignored
- **AIR-6750** — Codex: `~/.codex/config.toml` not respected (custom model provider invisible)
- **AIR-3733** — Claude: `permissions.allow` in `~/.claude/settings.json` not honored
- **AIR-5270** — Codex/Claude/Gemini: native hook configs not executed after sync
- **AIR-4564** — Claude: cannot point Air at a custom config directory
- **AIR-4078** — Junie: how to inject custom guidelines into an ACP session

### Likely root cause (hypothesis — needs confirmation in the Air client repo)

Air's agent-integration layer appears to build each agent session from **Air's own settings
model**, passing a synthesized prompt/configuration to the agent, without reading the agents'
native config roots (`.junie/`, `~/.claude/`, `~/.codex/`). Because each agent is wired
differently — Junie over ACP (per AIR-4078), while AIR-6750 notes Codex *doesn't* support ACP —
there is no single config surface to import from, which is exactly why the gap surfaces once per
agent instead of as one bug.

### Concrete lead for whoever implements this

**AIR-4078 already documents Junie's supported injection points**, which is the cheapest path to
the *"guidelines"* half of this ticket:

- `--guidelines-filename <path>` CLI flag
- `JUNIE_GUIDELINES_FILENAME` environment variable
- both accept either a single `.md` file **or a directory** of `.md` files

Wiring Air's Junie launcher to point at the project's `.junie/` directory would likely close
**AIR-6772 as well as** the guidelines portion of AIR-6778. Worth scoping the broader work as
"read agent-native config roots at session start" so AIR-6772 / AIR-6773 / AIR-6750 / AIR-3733
are addressed by one change.

### Suggested order of work

1. Decide duplicate-vs-umbrella against **AIR-3466** first, to avoid parallel work.
2. If kept, re-scope to the cross-agent problem rather than Junie-only.
3. Take the AIR-4078 flag/env-var route as the Junie quick win.
