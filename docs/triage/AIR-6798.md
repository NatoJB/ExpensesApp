## Likely root causes, ranked

### 1. Mid-turn wedge that no restart can reconcile — AIR-6404 (most likely)

[AIR-6404](https://youtrack.jetbrains.com/issue/AIR-6404) — *"Agent chats ghost as unstoppable Running after an unclean exit — task-list items persist `AgentSessionState.Running` with dead `connectionParams` and are never reconciled on restart"* — is a near-verbatim symptom match, including the part that makes AIR-6798 unusual:

> "Stop does nothing, follow-ups don't render, and the chat stays 'running' forever, **surviving any number of Air restarts**."

Its first comment (forensics from build `262.132.21`) also records the no-crash variant, which fits AIR-6798's mid-turn interruption:

> "During long, tool-heavy turns the chat freezes mid-turn by itself: progress stops rendering, Stop stops responding, and the chat never recovers — not at turn end, not on follow-ups, and (per the reconciliation bug above) not across restarts either."

Per that analysis, each task-list item durably persists the session descriptor wrapped in `fleet.ai.protocol.agents.ship.AgentSessionState.Running`, whose `connectionParams` embed the RPC endpoint and auth token of a now-dead workspace process. A graceful shutdown rewrites items to `Suspended`; the unclean path never does, and startup never reconciles the wrapper against reality — which is exactly why reboots don't help.

**Status:** Fixed in build `262.531`, Fix version `262.579`, state *Ready for test*. **The reporter has not received this fix.** Every Air build seen in August 2026 bug reports is older: `262.132.34` (16 reports), `262.132.31` (5), `262.428` (5), `262.430` (1).

### 2. Credits exhaustion mid-turn is not a recoverable error path (not fixed)

This is the part AIR-6404 does **not** cover, and it is the reporter's stated trigger — running out of credits, then upgrading.

* [AIR-6413](https://youtrack.jetbrains.com/issue/AIR-6413) (Normal, Licensing, **Submitted**) — "Running out of JetBrains AI credits crashed Codex session". Same trigger class, still open.
* Why the upgrade didn't unblock it: Air is known to hold stale license/quota state after a plan or balance change — AIR-5458 "Air doesn't see top-up credits", AIR-5504 "Air is erroneously displaying 0 monthly credits left", AIR-4159 "Air doesn't detect AI Ultimate plan", AIR-6155 (Major, 2 votes) "Quota exhausted banner is shown when BYOK used". A *"refresh quota"* action had to be added in AIR-4109 precisely because of this staleness.

Combined hypothesis: the quota-exhausted condition terminates or wedges the in-flight turn, the client keeps a cached exhausted/unauthorized state so the upgrade doesn't restore service, and the AIR-6404 reconciliation gap makes the wedged session permanent across restarts.

### 3. An unhandled agent event freezes the whole turn (not fixed)

[AIR-6167](https://youtrack.jetbrains.com/issue/AIR-6167) (Major, Agent Integration, Submitted) — a single `session/update` the frontend can't handle throws `Failed to handle agent event` and the transcript stops advancing for the rest of the turn, with queued prompts never dispatched. A quota-exhausted / `402`-class event arriving mid-stream is a plausible instance of exactly this. Related delivery-starvation variant: [AIR-6166](https://youtrack.jetbrains.com/issue/AIR-6166) (fixed in `262.531`).
