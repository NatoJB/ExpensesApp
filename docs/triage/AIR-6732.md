## 4. Scope — the thing most likely to go wrong

Air has **two distinct banner families**, and the phrase "several instances of such promo banners" does not by itself draw the line. Whoever picks this up should fix the boundary *before* writing code, or `PromoBanner` will drift into being a generic `Banner` and absorb the alert cases.

**In scope — promotional / discovery / upsell** (these are the "several instances"):

| Issue | Banner | State |
|---|---|---|
| AIR-4111 | Promote **"Add Agent"** when several agents are connected | Fixed (UX) |
| AIR-4965 | Promote **EmbArk CLI installation** (conditional on server indices + CLI absent) | Fixed (Chat) |
| AIR-4061 | **Customize Air** banner on the Startup Page | Ready for test (UI) |
| AIR-5906 | **GitHub app connection** banner — borderline: an auth call-to-action styled as a promo | Fixed |

**Out of scope — status / alert / error**, which have different dismissal semantics, different severity styling, and are often transient:

AIR-6155 (quota exhausted) · AIR-3893 (capacity exhausted) · AIR-6516 (no Git repository found) · AIR-6570 (untrusted folders) · AIR-3405 (previously-completed-task banner) · AIR-4259 (misleading success banner).

**Worth folding in while consolidating:** **AIR-5530** — *"Chat banners' width does not support the full width"* (Bug, Verified). A shared component is the natural place for that layout contract to live once instead of per-site, and it is direct evidence that the current copy-paste approach has already produced a real layout defect.

## 5. The timing problem — read this before starting

**Air's UI is mid-migration from the in-house Noria runtime to the Compose runtime, and the Air UI Kit is inside the blast radius.**

This is not incidental context; it is the main scheduling risk on this ticket. Evidence from the open UI backlog:

- A dedicated workstream of ~15 `Compose:` issues (AIR-6087 – AIR-6111) sits in `Subsystem: UI`, several `In progress`.
- **AIR-6097** — *Replace click-through overlays in **Air UI Kit*** — explicitly reworks UI Kit patterns for "vanilla Compose hit testing", warning that the sibling-overlay pattern must be replaced with nesting.
- **AIR-6088** — the component **Gallery** application (*"formerly Noria Gallery"*) is itself being ported to the Compose runtime. That Gallery is where a new UI Kit component would normally be registered and demoed.
- **AIR-6726** (`Major`, In progress) — 15 focus-system conformance failures between the two runtimes; focus behaviour is not yet equivalent.
- **AIR-6104** — publishing the `fleet/compose` branch to the Compose dev Maven is still open.

**Practical consequence:** a `PromoBanner` written today against Noria is a near-certain rewrite, and one written against Compose may not have a stable published artifact to build on yet (AIR-6104). The cheap, low-risk sequencing is to land the **API surface and the Figma-derived design tokens** — variants, dismissibility, CTA slots, icon/illustration slot — which survive either runtime, and defer final rendering until the Compose target is decided. This is why the recommendation above is to leave the issue in `Submitted` rather than move it to `Ready for dev`: the runtime target is a genuine open question, not an oversight.

Someone on the Compose workstream should be the one to answer it.
