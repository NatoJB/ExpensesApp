### Likely root causes (ranked)

**1. Post-callback Code Assist bootstrap fails, not the callback itself.** This is the strongest candidate and it contradicts the reporter's own guess. In AIR-4562 the OAuth callback *succeeded* and the hang came afterwards, when the Code Assist onboarding response failed to deserialize:

```
💥ERROR💥 google.codeassist] Failed to fetch Code Assist info
kotlinx.serialization.MissingFieldException: Field 'cloudaicompanionProject' is required
for type 'fleet.oauth.google.common.LoadCodeAssistResponse', but it was missing at path: $
    at fleet.oauth.google.common.GoogleCodeAssist...
```

The UI never leaves "Waiting for login in browser" because nothing transitions it after that throw. `fleet.oauth.google.common` / `GoogleCodeAssist` / `LoadCodeAssistResponse` is the place to look, and `cloudaicompanionProject` should almost certainly be nullable with a real error surfaced to the UI instead of a hang. Still-open issues with the same signature: **AIR-5416** ("Code Assist did not return a Cloud AI companion project") and **AIR-6262** (endless loop when the account is not eligible for free-tier Code Assist). Note AIR-4562's own comment thread: the gemini-cli workaround did **not** work for a user on Code Assist Standard bound to a GCP project, which suggests the original fix only covered some account tiers — consistent with a fresh report on 262.

**2. Loopback callback port already bound.** AIR-4821 shows the callback is `http://localhost:10200/oauth2callback`. Per **AIR-5115**, Air does not check whether the callback port is free before using it, and the reporter there fixed it by killing the process holding the port. AIR-6449 (same "Waiting for Login in Browser" hang) resolved itself after a reboot, which fits a stale listener. Cheap to confirm on the reporter's Fedora box: `ss -lptn 'sport = :10200'`.

**3. Browser-to-IDE handoff / focus.** Lowest probability. AIR-6611 ("Air App is not focused on successful login in browser") is fixed in 262.565, *later* than the reporter's 262.132.34 — but that is a focus bug, not a hang, so it likely explains a different complaint.
