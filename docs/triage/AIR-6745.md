### Likely root cause of the difficulty

WinSparkle assumes it can (a) locate update resources inside the application image and (b) execute an installer
that overwrites the install directory in place. MSIX breaks both: packages are installed into a
system-managed, read-only location under `WindowsApps`, are signature- and identity-bound, and can only be
serviced through the platform deployment stack (`PackageManager` / App Installer). The `HRESULT(0x80070716)` in
AIR-5406 is an early symptom of assumption (a) failing even in the *pre*-MSIX installer build — so option 2
("keep using WinSparkle, try to install MSIX packaging via it") is the option most likely to dead-end. Weight the
investigation accordingly.
